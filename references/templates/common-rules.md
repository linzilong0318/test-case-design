## 零、测试用例编写通用规则（所有测试类型必须遵守）

1. **步骤必须给出具体数据**：测试步骤中必须直接给出具体的输入值、参数、操作对象，让测试人员可以照抄执行，不得使用描述性语言代替。
   - ❌ 不合格：`输入超长字符串`、`输入特殊字符`、`输入测试攻击向量`、`填写表单必填字段`、`发送带错误参数的请求`
   - ✅ 合格：`输入 ' OR '1'='1`、`输入 <script>alert(1)</script>`、`输入 用户名:testuser, 密码:Test@123456`、`发送请求，参数 name 设为空字符串 ""`
2. **大量数据例外**：当测试需要输入大量内容时，允许用描述性语言 + 明确参数说明，无需完整写出全部内容。大量数据的判定标准：
   - 文本输入 > 1000 个字符
   - 文件上传 > 1MB
   - 列表/表格数据 > 50 行
   - 其他明显不适合完整写出的场景
   - ✅ 合格：`在文本框中粘贴一段 10000 个汉字的文本（可重复"测试"二字 5000 次）`
   - ✅ 合格：`上传一个大小为 500MB 的压缩包文件（内容为随机生成数据）`
   - ✅ 合格：`在搜索框中输入一个包含 2000 个字符的随机字符串（可用 Python: "A"*2000 生成）`

## 一、测试类型分类

### 1. 功能测试
验证功能是否按需求规格正常工作，确保所有功能点正确实现。

**子类型**：增删改查（CRUD）、表单验证、状态流转、业务规则、数据校验

**示例**：登录功能、表单提交、数据查询、列表操作、状态流转

---

### 2. 接口测试
验证 API 接口的功能、状态码、数据校验、认证授权、安全性和错误处理。

**子类型**：功能测试、状态码验证、数据校验、认证授权、安全测试、错误处理

**示例**：GET/POST/PUT/DELETE 请求、Token 认证、参数校验

---

### 3. 兼容性测试
验证系统在不同环境下的兼容性，确保一致体验。

**子类型**：平台兼容、浏览器兼容、设备兼容、版本兼容

**示例**：不同机型适配、不同浏览器布局、版本升级兼容

---

### 4. UI 测试
验证界面显示和交互是否正确，确保用户体验。

**子类型**：布局测试、样式测试、交互测试、主题测试

**示例**：页面错位、样式不一致、动画卡顿

---

### 5. 性能测试
验证系统的性能指标是否达标，确保流畅体验。

**子类型**：响应时间、并发能力、资源占用、稳定性

**示例**：首屏加载慢、卡顿闪退、高并发崩溃

---

### 6. 可用性测试
验证系统的易用性和用户体验，确保易学易用。

**子类型**：导航测试、表单测试、帮助测试、可访问性

**示例**：操作繁琐、提示不明确、无法键盘操作

---

### 7. 联动测试
验证不同模块/组件之间的数据同步和状态联动。

**子类型**：表单联动、列表联动、搜索联动、状态联动、数据联动

**示例**：省市区联动、筛选条件联动、跨页面状态同步

---

### 8. 路由测试
验证页面路由跳转、参数传递和权限控制。

**子类型**：导航跳转、浏览器导航、路由参数、深链接

**示例**：直接访问 URL、404 处理、登录拦截

---

### 9. Agent 测试
验证 AI Agent（智能体）的任务完成度、工具调用、记忆管理、安全边界等。

**子类型**：任务完成度、工具与记忆、安全与边界、性能体验、内容质量、知识库调用

**示例**：意图理解、多步骤任务执行、工具调用的准确性

---

## 二、优先级判定规则

### P0 - 致命（Critical）→ API priority = 0（高）
- 核心功能
- 影响主流程
- 导致系统崩溃
- 数据丢失

**处理**：立即修复，阻塞发布

---

### P1 - 严重（Major）→ API priority = 1（中）
- 重要功能
- 影响用户体验
- 功能错误
- 界面严重问题

**处理**：尽快修复，影响发布

---

### P2 - 一般（Minor）→ API priority = 2（低）
- 次要功能
- 轻微体验问题
- 界面小问题
- 提示信息不准确

**处理**：排期修复，可带病发布

---

### P3 - 建议（Trivial）→ API priority = 2（低）
- 优化建议
- 界面美化
- 不影响功能

**处理**：有空再改

## 四、API 格式适配

> 以下规则用于适配后端 `/api/v1/testcase/save` 接口的字段格式要求。

### 4.1 批次号（batchNo）

- 格式：`yyyyMMddHHmmssSSS`（年月日时分秒毫秒，共 17 位数字字符串）
- 同一批次生成的所有用例使用**相同的 batchNo**
- 生成时机：阶段二开始组装用例时生成
- 示例：`20260709143025123`

### 4.2 优先级 int 映射

| 判定标准 | P 级 | API priority (int) |
|---------|------|-------------------|
| 核心功能、主流程、系统崩溃、数据丢失 | P0 | 0 |
| 重要功能、体验影响、功能错误、严重 UI 问题 | P1 | 1 |
| 次要功能、轻微体验、提示不准确、优化建议 | P2 / P3 | 2 |

### 4.3 测试类型 int 映射

| type (int) | 测试类型 | 说明 |
|-----------|---------|------|
| 1 | 功能测试 | CRUD、表单、状态、业务规则 |
| 2 | 接口测试 | API 功能、状态码、认证、安全 |
| 3 | 兼容性测试 | 平台、浏览器、设备、版本 |
| 4 | UI 测试 | 布局、样式、交互、主题 |
| 5 | 性能测试 | 响应时间、资源占用 |
| 6 | 可用性测试 | 导航、表单、帮助 |
| 7 | 联动测试 | 表单联动、数据联动 |
| 8 | 路由测试 | 导航跳转、路由守卫 |
| 9 | Agent 测试 | 任务完成度、工具调用、安全边界 |

### 4.4 字段名映射

| 旧字段名（已废弃） | 新字段名（API 格式） | 说明 |
|------------------|-------------------|------|
| `caseId` | `caseCode` | 用例编号，编号规则不变 |
| `testType` (string) | `type` (int) | 测试类型改为编码 |
| `priority` (P0-P3) | `priority` (0-2) | 优先级改为 int |
| `prerequisites` | `preconditions` | 前置条件 |
| `dimension` | 已移除 | 不再需要 |
| `actualResult` | 已移除 | 不再需要 |
| `status` | 已移除 | 不再需要 |
| — | `batchNo` | 新增，批次号 |

### 4.5 换行符说明

- **API JSON 格式**：使用 `\n` 换行（JSON 转义换行符）
- **Markdown 表格格式**：使用 `<br>` 换行
- 两者内容相同，仅换行符表示方式不同
